GYM PLAN GENERATOR – PROJECT FACTS (source for the presentation)

Author: Daniil Kryvoruchko · Final project, Passerelle program, BFH (Berner Fachhochschule) · Presentation: 29 October 2026

WHAT IT IS
A Java web application that creates personal gym training plans. The AI (Google Gemini) proposes the plan; my own Java code validates the input, checks the AI's answer and calculates calories and macros itself.
Core message: "The AI provides the ideas. My code provides structure, validation and correct numbers."

PROBLEM
- Generic training plans from the internet rarely fit a person's goal, time and equipment.
- A chatbot gives unstructured text that nobody checks.
- Experienced lifters need concrete values: RIR (reps in reserve), weekly sets per muscle group, calorie targets.

GOALS
1. A plan that fits the person (goal, experience, equipment, days, time per session).
2. Do not trust the AI blindly: a JSON schema forces the structure, my code checks the content and calculates the numbers.

TECH STACK
Java, Spring Boot 4, Bean Validation, Maven, Thymeleaf, HTML, CSS, JavaScript, Gemini API (model gemini-3.5-flash-lite) with JSON schema, IntelliJ, Git and GitHub.

THE FORM (14 fields)
Age (18 to 80), sex, height, weight, optional body fat percentage, experience, goal (Cut, Aggressive Cut, Lean Bulk, Bulk, Strength, General Fitness), equipment (full gym, dumbbells only, bodyweight only), training days per week, minutes per session, preferred split (let the AI decide, full body, upper/lower, push/pull/legs), optional desired exercises, optional focus muscles, plan language (English, German, Ukrainian).

HOW A REQUEST WORKS
1. Validation: Spring checks every input on the server (@NotNull, @Min, @Max, @Pattern, @Size). An extra rule: push/pull/legs needs at least 3 days, upper/lower at least 2. Errors appear next to the fields; the input is kept.
2. Prompt: PromptBuilder turns the form values into a prompt. Free-text fields are cleaned (line breaks and angle brackets removed, max. 200 characters) and marked as wishes only, as protection against prompt injection.
3. Gemini call: GeminiClient sends the prompt with a JSON schema, so the answer always has the same structure. The API key comes from an environment variable and is never in the code or on GitHub.
4. Check: PlanService reads the JSON into the Java classes Plan, Day and Exercise. PlanChecker checks the content: correct number of days, sets 1 to 10, RIR 0 to 5, valid muscle group, names and reps not too long. If the plan is invalid, Gemini is asked again, up to 3 attempts in total. After that the user sees a clear error message.
5. Calculation: NutritionCalculator (plain Java, no AI) and VolumeCalculator.
6. Result page: one card per training day with a table (exercise, muscle, sets, reps, RIR, rest), weekly sets per muscle, progression and deload advice, nutrition target.

NUTRITION CALCULATION (in Java, not AI)
- Resting energy: Mifflin-St Jeor; if body fat is given, Katch-McArdle (based on lean mass).
- Times an activity factor from training days: 1.375 (1-3 days), 1.55 (4-5), 1.725 (6-7).
- Goal change: Cut -20 %, Aggressive Cut -30 %, Lean Bulk +7 %, Bulk +15 %, Strength and General Fitness 0 %.
- Safety limits: maximum deficit 750 kcal (Cut) or 1000 kcal (Aggressive Cut); minimum 1500 kcal (men) or 1200 kcal (women).
- Protein 1.6 to 2.6 g per kg depending on goal; fat 25 % of calories (at least 0.6 g per kg); carbs = the rest.
- Example: man, 80 kg, 180 cm, 25 years, 4 training days, Cut → about 2240 kcal, 176 g protein, 62 g fat, 244 g carbs, about 0.5 kg weight loss per week.
- These are estimates, not medical advice.

FUNCTIONS FOR THE USER
- Validation with clear error messages
- Plan as tables, one per training day
- Weekly sets per muscle group; values under 10 or over 20 are marked as a hint
- Nutrition target with expected weekly weight change
- Result page fully in English, German or Ukrainian (message files)
- Copy the plan as text, print it or save it as PDF
- The button shows "Creating plan..." while waiting

CODE STRUCTURE
- Web layer: PlanController (shows and receives the form), PlanRequest (form fields and validation rules), LocaleConfig (language of the result page), HomeController (redirects / to /plan)
- Logic layer: PlanService (runs the generation and the retries), PlanChecker, NutritionCalculator, VolumeCalculator
- AI layer: GeminiClient (HTTP call), PromptBuilder (prompt text), GeminiException (error type with user-safe messages)
- Model classes: Plan, Day, Exercise, NutritionTargets
- Views: plan-form.html, plan-result.html (Thymeleaf), style.css, app.js

KEY CODE BLOCK 1 – retry loop in PlanService (simplified)
for (int attempt = 1; attempt <= 3; attempt++) {
    String text = geminiClient.generate(prompt);
    Plan plan = parse(text);
    List<String> problems = planChecker.check(plan, days);
    if (problems.isEmpty()) {
        return plan;
    }
}
throw new GeminiException("We could not create a valid plan.");

KEY CODE BLOCK 2 – calories in NutritionCalculator (simplified)
double bmr = 10 * weight + 6.25 * height - 5 * age + (male ? 5 : -161);
double maintenance = bmr * activityFactor(days);
double target = maintenance * (1 + calorieChange(goal));
target = Math.max(target, floor);

PROBLEMS AND SOLUTIONS
- Gemini model overloaded (error 503) → switched to the Flash-Lite model; errors appear on the form instead of crashing the page.
- AI answers are not always correct → JSON schema plus PlanChecker, with new attempts.
- API quota limit (error 429) → friendly message, limited number of attempts.
- Protecting the API key → only in an environment variable, never in code or on GitHub.
- Spring Boot was new for me → learned it step by step.
